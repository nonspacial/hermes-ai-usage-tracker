# Desktop pane DOX

## Purpose

Own the `desktop/plugin.js` Hermes pane, chart, navigation, query state and theme integration.

## Ownership

This subtree owns packaged UI source. Root owns the generated `preview.html` and its build script; tests/ui owns offline browser fixtures. Change source first, regenerate preview when authorised, then test parity.

## Local Contracts

- Read root instructions and [the Overview interaction contract](../docs/OVERVIEW_INTERACTION_CONTRACT.md) before modifying graph/filters. That document distinguishes requirements from verified behaviour; validate implementation, not just wording.
- Keep display name **AI usage +** and use host theme tokens throughout. Plot focus/selection styling, graph-only border and data-versus-selection resolution are specified in the linked contract.
- Filter graph, totals and records with one semantic scope, retaining selected profile/provider and outer period. Keep saved per-profile view choices separate (including provider choice and Overview filters); prevent stale asynchronous responses from overwriting a newer profile/view. All profiles remains read-only with qualified IDs and backend support checks.
- Keep identity-link activation separate from narrow-record disclosure. The five Overview breakdown identities filter in place; Requests retains its drill navigation. A Subagents identity selects the qualified subagent plus subagent agent scope, not merely the generic Subagents totals shortcut. Simple hover must not shade the whole cell. Do not fetch for a single graph click, hover or keyboard inspection; fetch only on a committed valid scope change.
- Lower lists use ten-record projected server pages, append on Load more and a single explicit complete View all response retained in renderer RAM. Preserve full-window chart/summary while paging rows, reject changed-generation/overlapping pages without replacing visible rows, and clear a frozen result on exit or scope change. CSV strips the list-only compression-kind filter with the projection/page keys; it exports requests in the full filtered window, not only the chosen compression type. See [record paging contract](../docs/RECORD_PAGING_CONTRACT.md). Skills and subscription records are separate.
- Include the committed tab and Overview group in the `/ledger` projection query and coordinator identity. Selected-profile Overview/time or model may use the signed `POST /ledger/refresh` receipt from a validated same-scope cached snapshot; the POST returns a complete replacement DTO, never client-side totals arithmetic. Check its exact version-1 included/omitted manifest for the requested group, required common/header and active breakdown nested entry shapes, receipt/revision and exact window before paint/cache admission; corresponding GETs must also validate consumed nested shapes before paint/cache. The provider, trend and selected model attempts are complete partitions of summary attempts; do not infer sum of distinct sessions, Decimal cost or partial/unknown token accounting. Malformed successful POSTs get one GET fallback while the prior snapshot remains labelled on failure; malformed GETs fail closed without recursive retry. Zero counts, empty zero-activity breakdowns, nullable project provenance and open marker end, and unknown coverage are legitimate. Forward both actual window bounds on a moving 24h interval; unsupported/expired/rejected receipts fall back to one GET. All-profile, saved marker, other views and CSV never POST. New scopes show pending until a validated same-scope renderer-RAM entry is found; revisits show that entry immediately with its historical generation/window/age, **Updating**, and an explicit failure state. Key by connection, profile, provider/model and every factual filter/window/view/group/page; validate current all-profile inventory identity (or unique selected identity) and backend analytics revision before display. Filesystem change tokens are hints, **not** data revisions: a changed hint does not prevent a clearly aged cache hit. If identity validation fails, do not replay cached rows. Skip mutable saved-marker entries rather than pretending their historical bounds are unchanged. The cache retains serialized projected payload strings only, with entry/count/TTL and 8 MiB serialized UTF-16 payload budgets; this is **not** an exact JavaScript heap cap. Entry metadata, pending responses and the parsed active view are outside that budget. Clear cache on plugin disposal, not pane unmount; a disposed owner cannot share an unresolved read with a new owner after a rapid return. Never stamp an old response with a new key or show previous group rows under a new label. Age updates while visible on a bounded timer and stops when hidden/unmounted. Bridge only shared header data under the same semantic filter/window/connection scope. Skills has a separate history query; CSV removes `view`/`group`/`list_mode`/`compression_kind` to fetch frozen-window full pages with sequence, coverage and catalog guards. No hover prefetch. Change tokens only schedule reads; force periodic full reconciliation even for non-rolling windows.
- Keep POST eligibility narrower than selected Overview GET validation: bucket and saved-marker GETs still validate their projected DTO and factual window before paint, but neither may resume. Compute the selected GET window by intersecting outer bounds with bucket bounds and marker facts from that response; an omitted end is server-resolved, and a disjoint marker/bucket can return a zero-width window with one zero-attempt zero-width trend row. If selected marker facts are absent from the returned tests list, fail closed rather than infer them from aligned Custom inputs. Preserve complete provider/trend partitions of the filtered summary; absent-mode Overview group arrays retain their complete attempt partitions, while `list_mode=page` deliberately includes only the selected lower group page and separately reports its count. A changed opaque hint across a successful read schedules a follow-up but does not veto storage of its validated same-inventory snapshot; only the signed response receipt can authorise a later incremental baseline. A manual Refresh owns one post-click read and releases its busy control when that read settles, even if dirty hints continue background reconciliation; a click during an existing flight joins its next follow-up without duplicating the active request. Read failures retain a matching prior snapshot with its age and error, and never label a healthy recorder Disconnected merely because analytics failed; recorder status failure/staleness is a separate health signal.
- The shared Codex reset header on Subscriptions and the provider card orders `Auto use` text, checkbox, then count badge before the card close button. An eligible positive badge opens the existing guarded confirmation directly; zero, unknown and ineligible counts open nothing. No intermediate balance popover or Refresh balance control. Keep account-bound backend redemption checks, opt-in and cancel/focus behavior intact.
- Provider navigation combines quota catalogue IDs and recorded provider IDs, but excludes the ledger's `unknown` attribution sentinel; All providers still includes those requests in totals, groups and records. Do not remove legitimate ledger-only providers.
- Skills uses three stable period reports: Frequency, Context footprint (estimated returned main-skill content) and Catalogue overhead (observed preflight description inclusion versus main loads). Its aggregate-only query follows the existing global profile/provider/period/model scope, fetches on opening/filter change/manual Refresh, and ignores per-request change notifications. Give each mounted report owner a distinct query/shared-read identity so a held predecessor cannot block a reopened read or paint its response; resolve rolling starts at each committed Skills read (including reopen and Refresh), while retaining fixed Custom/marker/bucket bounds and same-selection response identity. Unavailable/not-recorded coverage cannot be shown as a zero footprint; label partial all-profile totals as partial, while a readable empty selection can show a known zero. Catalogue overhead lists all skills, so suppress its irrelevant selection banner without clearing Frequency/Context selection. Keep the existing chart, legend, table, theme and responsive controls. Historical detail rows remain server-side; do not restore the retired Session timeline or a latest-snapshot selector.

## Work Guidance

- `preview.html` embeds this source and a synthetic fixture; it cannot independently establish native host behaviour. The old preview React 16 shim lacks pointer events; use the existing native-event/batched adapter for gesture tests rather than treating unavailable shim handlers as production bugs.
- Compact K/M/B token quantities use four fractional digits through the shared `short` formatter; sub-1,000 token amounts and chart ticks retain their previous non-compact precision, exact token details use `count`, and money, percentages and request/session counts retain their own formatters.
- Explanatory HTML `title` sites (header/chip, reset badge, provider controls, metrics/notes, filters and rows, JSON/cost/rate controls, refresh/reconnect) and chart/Skills SVG `<title>` sites share the Auto use tooltip surface via scoped event delegation. The fixed popup wraps inside the viewport, resolves its theme tokens from the owning pane (including live overrides), and is exposed as an accessible description on hover/focus. Pointer travel onto an untitled sibling retains a focused owner's tooltip. Native title text is suppressed only during display, then restored; SVG titles remain owned by React and active text updates refresh the popup and temporary accessible label. Native `<option title>` is intentionally left to the browser because select popups are outside the pane DOM. The Auto use inline tooltip retains its label/checkbox description and is viewport-bound on very short panes. `ErrorState`'s `title` prop, the chart heading class and local `title` variables are labels/content, not tooltip implementations.
- Preserve tooltip reachability by keyboard and during drag, click-away focus clearing, correct selection highlights and host-token live updates. Interactive Skills pie slices have focusable named button semantics and Enter/Space selection alongside the existing legend controls. The header Refresh hover uses the shared accent and selected-background tokens only when enabled; focus remains visible, disabled actions retain normal disabled styling and the original refresh handler is unchanged.

## Verification

- `node --check --input-type=module < desktop/plugin.js`.
- For small scoped cache changes, run the affected cache browser script, syntax, generated-preview parity and diff hygiene; do not run unrelated backend suites or all-browser sweeps.
- When preview regeneration is in scope: `.venv/bin/python build_preview.py`, then run relevant standalone `tests/ui/test_chart_interactions.py`, `test_overview_identity_filtering.py`, and view-persistence browser scripts with `CHROMIUM_PATH` set. These exercise synthetic data; they do not prove live host capture or native clipboard.
