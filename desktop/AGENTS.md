- **Live read cadence** (`makeLedgerCoordinator`/`useLiveLedger`). Real time is mandatory: a recorder `changed`/`connected` frame, marker action or reconnect calls `hint()`, which starts a full read after the fixed 150ms debounce (`LEDGER_HINT_DEBOUNCE_MS`) and repaints on settle; never lengthen, rate-limit or drop this path. At most one full read per coordinator is in flight: hints, change polls and expiry during a flight mark it dirty and yield exactly **one** trailing read (150ms, 0 for manual Refresh, backoff after failure); hints while a read is queued join it. No caller ever waits for another caller's change-token probe. A read's own pre- and post-read checks return null at once while any probe is in flight (as on main), so a held or slow probe never delays `GET /ledger` past the debounce or delays its publish; a null token certifies nothing (no cache admission, the next expiry cannot skip). Poll and expiry share the latest in-flight probe only when it began after both the latest notify hint/manual Refresh and the latest read start, else they start their own; an expiry answer is discarded if a hint or read started meanwhile. Each read keeps a pre-read and post-read token (the pair certifies the response, drives follow-ups and cache admission); the pre-read token may reuse the newest-started answered probe (poll, expiry or the previous read's post-read check) no older than 2s, never one that predates a notify hint or manual Refresh. `GET /ledger/analytics` runs before **every** read, as before this cadence work: a changed revision publishes `{data:null, invalidated:true}` (pending, no rows) before that read's response is admitted. Rolling windows are re-evaluated every visible minute by `expire()`, not `hint()`. An open-ended Custom window (`growing`: Custom, empty end, no chart bounds, no saved marker) also ticks `expire()` every visible minute, but never takes the skip path: each tick reads after the 150ms debounce (the old 60s behaviour), omitting `end` so the server resolves now; `growing` is part of the `useLiveLedger` key. Because a growing open-ended Custom view refetches each visible minute, appended Load-more pages are replaced on each read, as with rolling windows. A tick during a flight is re-evaluated when the flight settles; a tick with a read queued joins it; otherwise it reads after the same 150ms debounce as a hint unless a skip is **permitted**. A skip is permitted only when all of the following hold, else the tick reads (the old 60s behaviour): a full read started < 5 minutes ago (`LEDGER_RECONCILE_MS`); change checks supported and not failing, no failure backoff pending; not the Compressions view; the displayed response came from a full read whose pre/post tokens matched, and a fresh probe (no hint, read or Refresh since it began) returns that same token; and `rollingEdgeStable` proves from the response itself that every displayed field is unchanged at the new edges — neither edge crosses a trend bucket; the leading bucket has zero attempts and an observed peak of 0/null; `summary.pending===0` and `summary.unresolved===0` (execution state changes without a write); `compression_count===0` and no compression rows (compressions are counted by start time and have no per-bucket count); `quota_observations` absent or empty; `crossing_start`/`crossing_end` absent/null; `price_catalogs` absent or every entry already `stale` (the flag flips at a UTC-day change without a write); `cache_read_progression` absent or the read has no factual request filter (its boundary predecessor is any same-session main request); and no top-level field outside `ROLLING_SKIP_FIELDS`. Missing or malformed evidence forbids the skip. A permitted skip publishes the same response with only `window` and trend/time-row edges equal to it advanced; totals, rows, `seq` and generation are untouched, and it is never cached or used as a resume baseline. Because the matching token probe is a backend confirmation that nothing was written, the skip publishes `received` = the probe time: the freshness badge age reflects the last backend confirmation (full read **or** token-confirmed skip) and resets each minute as it did when every tick read. Closed fixed windows (and an open saved marker) reconcile with a full read every 5 visible minutes; visibility return runs a change check plus `expire()`/`hint()`.
