## Chart and window

- Use Hermes host theme tokens for controls/graph, never a separately guessed palette. The focused/selected plot stroke is **1 CSS pixel** with non-scaling vector effect and uses `--ui-accent`, identical to the selected line and button text. Hover selection background uses `--au-selected-bg`; focused accent and hover are distinct when the theme defines them so. Theme changes must update both live. Draw the border on the plot only, not the full chart/card.
- Clicking a data point or using keyboard inspection updates accessible focus/tooltip without querying. Clicking away clears graph focus. Tooltips remain usable from keyboard and while dragging; neither hovering nor an uncommitted drag fetches.
- For a 30-minute view, data aggregation uses one-minute buckets; for a one-hour view, two-minute buckets. **Data resolution is separate from the selectable time grid.** Draw chart geometry against actual returned bucket edges, including clipped calendar-view edges, rather than inventing fixed sample timestamps; only returned edges on the half-hour grid are selectable drag bounds.
- A committed view/drag range is at least 30 minutes. Graph drag and Custom start/end inputs share selectable `:00`/`:30` half-hour wall-clock boundaries. Validate typed and pasted values, ordering, grid alignment and minimum duration **before** fetching; invalid input never issues a request. At the 30-minute minimum no further drag zoom is allowed.
- Drag activation uses the midpoint at 15 minutes to select the minimum 30-minute range, not an arbitrary pixel threshold. Retreat before release cancels, even if a tentative preview was shown. Forward/reverse drags and clipping at edges must agree; highlight exactly the committed bounds. A click, jitter, same-boundary gesture or cancelled pointer gesture does not zoom/query.
- Keep measurement/test-marker timestamps exactly as recorded. Align only the visible Custom input bounds around an open/closed marker; the server intersects the saved factual marker, bucket and custom/outer period with half-open end semantics. Within-marker chart zoom and Custom input edits retain that intersection. A visible Saved marker control explicitly removes it to permit viewing the aligned fringe; switching to an outer period also replaces the marker selection. No marker may be shifted for a test or read widened beyond its recorded interval while selected. Persisted old off-grid Custom inputs must not silently issue an unconstrained read.

## Overview identity filters

- In Overview's **Model**, **Hour** (or its Minute/Day resolution), **Project**, **Session** and **Subagents** breakdowns, identity text is an actionable link applying a filter **in place**: remain on Overview and update graph, totals and records together, while retaining profile/provider and outer period. Do not shade the whole cell on hover; only the identity link needs hover affordance. Narrow cards keep the link separate from disclosure/expand. Unattributed sentinel identities are not actionable; the Subagents breakdown link selects that qualified subagent and the subagent agent scope, whereas the totals shortcut selects all subagents.
- Model identity means provider **and** effective response model for requests (prefer non-empty recorded response model over requested model). Skills and Compressions filter against their **own recorded provider/model**; exclude unknown/unattributed events rather than borrowing the request/session model. Time breakdown uses returned bucket start/end, intersected with any marker and outer time window; session family/subagent qualifiers follow backend semantics. Projects/sessions/subagents in All profiles retain qualified profile identity and sentinel safety.
- Preserve the existing filter-chip/clear/back grammar and Requests drill paths; Overview identity activation itself must not navigate to Requests. Narrowed filters also affect sibling analytics routes consistently; switching an outer period must clear its previous selected bucket rather than resurrect it. Persist view choices per profile, including provider and scope filters, and guard against stale responses overwriting the current view.
