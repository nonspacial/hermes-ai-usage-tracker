## Chart and window

- Use Hermes host theme tokens for controls/graph, never a separately guessed palette. The focused/selected plot stroke is **1 CSS pixel** with non-scaling vector effect and uses `--ui-accent`, identical to the selected line and button text. Hover selection background uses `--au-selected-bg`; focused accent and hover are distinct when the theme defines them so. Theme changes must update both live. Draw the border on the plot only, not the full chart/card.
- Clicking a data point or using keyboard inspection updates accessible focus/tooltip without querying. Clicking away clears graph focus. Tooltips remain usable from keyboard and while dragging; neither hovering nor an uncommitted drag fetches.
- Show the selected bucket's UTC timestamp, exact counts and missing-usage or partial-price qualification as an accent-coloured footer below the existing chart tooltip instructions, not as a separate visible chart-pane line. The shared popup retains its theme, wrapping and viewport clamp; its live footer follows pointer and keyboard inspection. Keep the no-activity message when the window is empty.
- For a 30-minute view, data aggregation uses one-minute buckets; for a one-hour view, two-minute buckets. **Data resolution is separate from the selectable time grid.** Draw chart geometry against actual returned bucket edges, including clipped calendar-view edges, rather than inventing fixed sample timestamps; only returned edges on the half-hour grid are selectable drag bounds.

Validate typed and pasted values, ordering, grid alignment and minimum duration **before** fetching; invalid input never issues a request. At the 30-minute minimum no further drag zoom is allowed.
- Drag activation uses the midpoint at 15 minutes to select the minimum 30-minute range, not an arbitrary pixel threshold. Retreat before release cancels, even if a tentative preview was shown. Forward/reverse drags and clipping at edges must agree; highlight exactly the committed bounds. A click, jitter, same-boundary gesture or cancelled pointer gesture does not zoom/query.

## Peak observed subagents (repository candidate; synthetic checks only)

- `subagent_start`/`subagent_stop` event timestamps are paired by child session in durable event **sequence** order (not timestamp order); clock-shifted pairs with non-positive timestamp length are rejected after pairing. Only strictly positive, matched half-open intervals count. An unmatched stop, duplicate/overlapping start, open start or non-positive pair is excluded; `unmatched` counts **each** excluded recorded notification, including every start and stop of a rejected ambiguous/non-positive pair. An open child is **not** presumed to end at the report boundary. Repeated sequential child sessions can share an agent identity, but concurrent intervals with the same identity count once. A carried-in matched lifetime intersects the selected factual window even if its start precedes that window. Main agents never count.
- `peak_observed.value` is the maximum number of distinct child identities simultaneously present in matched intervals intersecting `[window.start, window.end)`, not the maximum true concurrency. `null` means no matched lifecycle evidence (unknown), whereas `0` is an observed zero in a window with matched lifecycle evidence elsewhere. `unmatched` counts excluded lifecycle notifications across the readable snapshot, not missing notifications that were never recorded. Missing hooks and incomplete coverage can undercount. No request start/end is used as a substitute lifetime.
- The unfiltered period and trend buckets include matched lifetimes regardless of request rows. Provider, effective-response-model, project and root-session group values are attributed only where a matching child-session request was recorded in the selected request window; a scoped request filter likewise requires recorded matching evidence. These scoped peaks are **request-attributed observations**, not independently identified lifecycle provider/model facts. Groups with no evidence do not inherit an unfiltered peak. The selected period's peak is independent of lower-list pagination. All-profile period, provider/model and bucket peaks sweep the union of profile-qualified intervals, never the sum of per-profile peaks. Sources are independent snapshots and partial/missing profile coverage remains qualified.
- Placement: the graph's selected-point accent tooltip footer contains the bucket peak; provider rows beside the graph and the Subagent tokens card contain period/provider peak; Model, time, Project and Session breakdowns display their own scoped peaks. Do not add a vacuous per-subagent column. The compact tooltip explains unmatched/open observations, request-derived grouping and non-simultaneous profile snapshots. Retain existing theme tokens and chart/tooltip interaction.
- Signed nonpaged selected-profile Overview/time or model GET receipts are supported on new journalled ledgers; POST keeps the request-only bounded reducer and recomputes all observed peaks from the same copied snapshot before returning/sealing a delta. Event-only lifecycle changes are observed, while old signed receipts lacking peak fields fall back to a full read. Paged pane reads remain GET-only, and old ledgers remain full reads. Renderer cache entries still require exact scope/generation and retain their age/Updating labels. A synthetic check counts one lifecycle pairing pass per delta with multiple affected request buckets; this is not a live speed guarantee.
