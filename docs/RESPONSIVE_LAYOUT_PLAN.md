# Responsive pane contract — pending visual acceptance

## Current prototype

- The actual **route tile** (border box, less its 16px insets for the content box), not monitor/window dimensions or `ResizeObserver.contentRect`, chooses the mode. The fixed split applies only when **pane width ≥850px AND pane content height ≥ the width band's minimum** below; otherwise the plugin root is the **sole vertical scroller** (one page scrollbar). In that single-scroller mode the upper, reader, record table and expanded JSON have no nested vertical scroll and are not clipped; document scrolling stays disabled. The user chose this short-medium fallback ("Use one page scrollbar at these sizes") over a split that left an unusable reader. The Skills legend's independent 620px width threshold is unchanged.
- **Fixed pane-size breakpoints.** The mode depends only on pane dimensions: it never depends on provider, page, subpage, loading or row count. Each height minimum is 16px top inset + the band's upper floor + 50px lower navigation + a **160px usable reader** (including the lower list controls) + 16px bottom inset:

  | Content width (pane − 32px) | Upper floor | Split when pane height ≥ | e.g. pane width |
  | --- | --- | --- | --- |
  | 818–900px (two-column provider grid) | 683px | **925px** | 850–932px |
  | 901–939px | 661px | **903px** | 933–971px |
  | 940–1435px | 652px | **894px** | 972–1467px |
  | ≥1436px | `clamp(547px, H − 242px, 608px)` (H = pane − 32px) | **789px** | ≥1468px |

  The band edges reuse the existing 901px provider-grid, 940px metric-row and 1436px provider-grid content-width breakpoints. `desktop/plugin.js` (`splitMinContentHeight`) and the named `au-pane` container queries use the same content widths. Examples: 850×750, 850×850, 980×850 and 1300×850 use the single scroller; 1920×1080 and 3840×2160 remain roomy splits.
- In split mode the upper track is `max(ratio, floor)`. The ratio is 55% upper / 45% lower on roomy panes, rising to 70/30 as height falls, excluding the insets. Each floor is the tallest fixture-known upper in its band, plus 2px: All providers with five providers, Codex two windows and Anthropic three windows (`Current session`/`Current week`/`Sonnet week`) as bars; the Anthropic three-row provider card; the Nous details. The two-column band assumes the worst row order. Below 1436px content width every split height is above the compact-chrome range, so the floor is constant. At ≥1436px it rises 1:1 with height into its cap, so a taller pane never shrinks the reader. At every breakpoint the reader is exactly 160px and grows above it. At ≥1300px pane height the ratio already exceeds every floor. Measured upper/reader heights (px): 850×925 683/160, 933×903 661/160, 972×894 and 1467×894 652/160, 1468×789 and 1920×789 547/160, 1920×1080 608/390, 3840×2160 1170.4/907.6.
- Bars, labels and summary text are **not** compacted or hidden, and the upper section never gets an inner scrollbar. Unknown catalogues with more provider rows or windows than the fixture can still exceed a floor. For example, three more two-window providers and a fourth Anthropic window need roughly 26–41px more at medium widths. In that case the reader shrinks below 160px, but the mode rule still depends on pane size only.
- The provider quota stays **full-width immediately below provider tabs** on every provider page and at every width, including all Nous Portal fields. In the ≥1436px band, compact chrome at ≤850px content height preserves that card, metric notes, graph plot and quality line above lower navigation; it does not relocate, disclose or hide accounting data. Lower Load more/View all actions only appear while more matching records exist (or a pending/failed operation needs recovery); Exit frozen view remains independent.
- In the single-scroller mode, the graph's SVG keeps the CSS height it uses at 849px width for a given pane height. Its viewBox follows the rendered SVG width and height, so the plot height is unchanged at every narrower width and on short medium panes (850×850 matches 849×850). Only entering the fixed split changes the graph height. The chart keeps its responsive width and compact axis labels, without text scaling. The split-mode graph remains flex-responsive.
- On any mode transition (width or height), transfer the keyed visible lower record and its offset to the new scroll owner. Later visible keys are fallback if a row disappears. If the first record/upper position cannot be represented by the shorter desktop reader, retain the mobile snapshot only for an unchanged-reader, same-page/filter round trip. A page/filter reset clears that pending snapshot and both scroll owners; returning to mobile starts at the new selection's top rather than replaying old pixels. Keep JSON/accordion nodes open and keyboard focus intact across same-scope resizing.
