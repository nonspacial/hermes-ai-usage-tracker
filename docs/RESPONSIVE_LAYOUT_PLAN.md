# Responsive pane contract — pending visual acceptance

## Current prototype

- The actual **route tile border box**, not monitor/window dimensions or `ResizeObserver.contentRect`, chooses the mode. The plugin root is the **sole vertical scroller** whenever pane width is below **850px** **or** pane height is below **750px**. Upper, reader, record table and expanded JSON have no nested vertical scroll in this mode; document scrolling remains disabled. This short-height exception is explicitly approved even in landscape. The Skills legend's independent 620px width threshold is unchanged.
- Only at **width ≥850px AND height ≥750px** does the non-scrolling root/upper use a fixed split with the lower reader as the vertical scroll owner. The track depends solely on pane dimensions, not provider, page, loading or row count: **55% upper / 45% lower** on roomy panes and **70% upper / 30% lower** at 850px height, excluding the 16px top/bottom insets. Navigation remains above the reader. Sparse upper content is top-aligned; the chart absorbs available upper space.
- The provider quota stays **full-width immediately below provider tabs** on every provider page and at every width, including all Nous Portal fields. Compact chrome at 750–850px high preserves that card, metric notes, graph plot and quality line above lower navigation at the fixed-split boundary; it does not relocate, disclose or hide accounting data. Lower Load more/View all actions only appear while more matching records exist (or a pending/failed operation needs recovery); Exit frozen view remains independent.
- Below 850px width, the graph's SVG keeps the same CSS height chosen at 849px for a given pane height. Its viewBox follows the rendered SVG width and height, retaining the 849px plot height at narrower widths; only the 850px pane-mode boundary changes graph height. The narrow chart still uses its responsive width and compact axis labels, without scaling the text or changing the root-only scroll policy. The ≥850px graph remains flex-responsive in the fixed split.
- On either width or height mode transition, transfer the keyed visible lower record and its offset to the new scroll owner. Later visible keys are fallback if a row disappears. If the first record/upper position cannot be represented by the shorter desktop reader, retain the mobile snapshot only for an unchanged-reader, same-page/filter round trip. A page/filter reset clears that pending snapshot and both scroll owners; returning to mobile starts at the new selection's top rather than replaying old pixels. Keep JSON/accordion nodes open and keyboard focus intact across same-scope resizing.
