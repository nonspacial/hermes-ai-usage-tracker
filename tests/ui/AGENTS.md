# Offline browser tests DOX

## Purpose

Exercise the packaged pane embedded in generated `preview.html` against synthetic fixtures.

## Ownership

`all_profiles_fixture.js` supplies offline fixture data and API simulation; `test_*.py` scripts exercise browser behaviour. Root owns the generated preview file and build command, desktop owns packaged UI source.

## Local Contracts

- Read root and `tests/AGENTS.md`; read `desktop/AGENTS.md` for UI contracts and [Overview interaction contract](../../docs/OVERVIEW_INTERACTION_CONTRACT.md) for chart/identity tests.
- Preview uses an older React 16 shim without pointer-event support. Gesture tests need the existing native-event/batched adapter; never conclude production is broken solely because shim handlers are absent. Regenerate preview from source plus fixture when in scope, then assert parity.
- Keep tests offline and deterministic: assert actual query traffic and visible/accessible behaviour, not just source regex or CSS selector presence. Use synthetic marker timestamps only in fixtures, do not alter real tests/ledger; aligned viewing inputs must not rewrite the saved marker. Cover the five in-place Overview identity links, qualified Subagents, provider/effective-model event exclusions, half-hour selection versus fine-grained data, and profile/provider persistence. Inspect async query ordering. The fixture emits sparse version-1 manifests, analytics revisions and inventory identities for projected reads, normalizes selected Overview/time/model synthetic summaries to the consumed backend wire shape, and preserves full legacy/CSV responses and null unknown coverage. `test_projection_browser.py` holds committed group/tab reads including rapid return, checks pending on cold views, labelled cached revisits with late-response isolation, sparse pages and full CSV. `test_ledger_memory_browser.py` exercises changed filesystem hint with held read, object-heavy serialized payload/eviction (not an exact heap cap), TTL, live age and hidden/unmount timer cleanup, rapid return/disposed flight, plugin disposal, connection/generation/identity isolation and failed updates. Refresh-geometry tests wait for the newly committed body before measuring a later refresh; an invalid Custom window must not show old rates.
- `test_incremental_browser.py` bridges isolated Playwright preview requests to real in-process FastAPI/TestClient responses: paged Overview refresh remains GET-only, failed GET retains the previous snapshot, group/CSV routes remain isolated, and a separate real eligible **non-paged** GET receipt → signed POST delta matches a fresh GET. The pane does not POST while `list_mode=page` because a delta cannot express page membership/count. Backend signed-POST faults and correction/zero-activity parity remain under `tests/test_incremental_refresh.py`; do not assert POST on a paged pane. `benchmark_incremental_browser.py` compares the historical non-paged GET/POST/forced-GET cycle, not current page-mode UI latency.
- `test_effective_window_browser.py` uses real in-process selected GET responses for a first-column populated Hour click, factual saved-marker and bucket intersections, disjoint zero-width response, filter clearing and malformed filtered GET bounds/nested/count rejection. It reopens a persisted old marker after 101 newer synthetic rows and requires chart/data paint from its returned authoritative fact. Do not use a preview grid timestamp as marker authority or let filtered GET validation depend on POST eligibility.
- `test_token_tooltip_refresh_browser.py` uses the offline preview to assert four-place compact token output without changing exact counts/costs, inventories mounted HTML/SVG tooltip sites including aggregate, open JSON and selected marker controls, checks focused-owner pointer fallback and SVG title mutation, compares pane-scoped live theme/geometry and the 320×180 inline warning, tests Skills pie keyboard/legend selection, and checks header Refresh hover with a changed accent and a disabled guard. The existing reset browser script accepts either the resting `title` or the same explanation temporarily moved to `data-au-tooltip` while the styled bubble is visible. Screenshots in profile scratch are fixture evidence, not product screenshots.
- UI scripts are standalone and should not be collected into the backend pytest suite; browser success is not native host or provider-capture proof.
- `test_record_paging_browser.py` checks lower-list append, mutation refusal, full frozen selected/all-profile DTOs, scope/exit reset and synthetic screenshots. The fixture pages projected rows without changing full-window chart totals; preview screenshots are not product gallery assets.
- The cache browser script covers completed Custom reads despite changed hints, sibling 24h/7d retention, and distinct fixed dates as well as identity, disposal and failure. It also holds an active read across a manual Refresh, drives a failed dirty follow-up, and checks that the manual control releases while the last good body and failure remain; an otherwise healthy recorder must not be labelled Disconnected by a usage read error. For narrowly scoped fixes, run affected scripts only; avoid unrelated whole-app/backend suites.
- `test_codex_resets_browser.py` uses only fake SDK reset responses to check text-checkbox-badge order in both cards, direct confirmation, no-action zero/unknown/ineligible counts, opt-in, cancellation/focus and guarded synthetic redemption. Never use a live account or enable auto use to verify this UI.
- `test_unknown_provider_navigation.py` adds synthetic unknown and legitimate ledger-only requests. The preview fixture derives recorded provider IDs from its request rows, as the backend does; the browser check keeps unknown usage in All providers while excluding the attribution sentinel from tabs and the narrow selector.
- `test_skills_usage_browser.py` exercises the three period aggregates, absence of the retired timeline/snapshot controls, model and period filters, no per-request refresh, manual Refresh, retained selection without a Catalogue banner and existing chart geometry at wide/narrow pane widths. `test_skills_coverage_rolling_browser.py` exercises unreadable/partial/known-zero profile coverage, a held old read across clock-advanced remount and stale completion, and committed rolling reads versus fixed Custom/marker reads without event-driven report polling. Synthetic preflight inclusion is distinct from historic skill loads; its screenshots in scratch are evidence, not product gallery assets.
- `test_connection_freshness_browser.py` exercises the badge's structured shared tooltip on hover/focus, original recorder explanation, scope-safe pending state, elapsed-age ticking and health-derived theme colours. Its screenshot is synthetic scratch evidence, not a product image.
- `test_chart_tooltip_browser.py` exercises selected chart point text in the shared tooltip's accent footer (including an all-unknown bucket), absent visible pane summary, instructions, hover/focus/keyboard/drag, live token changes and narrow viewport fit. Its scratch screenshot is synthetic, not a product image; `test_chart_interactions.py` retains the broader gesture and range checks.
