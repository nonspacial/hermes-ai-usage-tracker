# Test suite DOX

## Purpose

Verify ledger/backend behaviour and offline preview interactions without touching live Hermes profiles.

## Ownership

Root owns test dependencies and preview generation; this directory owns backend fixture tests and `conftest.py`. [ui/AGENTS.md](ui/AGENTS.md) owns standalone browser scripts and its fixture. `fixtures/` contains test assets under this owner.

## Local Contracts

- Read root and nearest child instructions. Use synthetic isolated homes/SQLite, offline pricing and no account credentials or live exports. Do not turn marker scenarios into fabricated production timestamps.
- Prefer executable behaviour tests over source-text regex. Assert provider/profile scope, response-model semantics, qualified aggregate identities, marker/bucket intersection, report/pagination parity and stale-response protection where applicable. `test_read_performance.py` compares complete selected/all-profile responses with the original unmaterialised SQL, counts fresh owner evaluations and benchmarks disposable requests; it does not read live ledgers or impose a flaky wall-clock threshold. `test_ledger_projection.py` compares every included projected field with the full fixture response, verifies omitted-field manifests, partial coverage, markers, empty/unknown data and hidden-stage nonexecution. `test_incremental_refresh.py` exercises transactional new-ledger revisions, signed resume/file identity, bounded journal bytes, canonical inventory/unknown-trigger or schema-object fallbacks, malformed JSON/shape/nested-price/catalogue preflight refusal with unchanged target/backup and no DDL (including negative saved, selected and unselected catalogue rates), finite/nonfinite/unknown/zero boundary parity with the accounting price validator, old rows beyond the first detail page/outside 24h, owned-open liveness refusal without process inspection, disposable catalog valuation and sparse legacy acceptance, mixed effective models across unchanged/changed buckets, omitted-end rolling route parity, token size/decompression, WAL/source sentinels, offline migration schema/backup/lock refusal and forced full fallbacks. `benchmark_incremental_refresh.py` is a separate executable synthetic timing fixture, not a pytest case. A test name or partial run is not completion evidence.
- `test_record_paging.py` covers the opt-in projected 10-row page and complete one-response list across 0/10/11/21, selected/all profiles, grouped latest-member recency and per-source bounded detailed hydration, row bounds and explicit full-report refusal without touching live data. Keep the absent-mode projection and CSV contracts unchanged.
- Test commands must not implicitly install or restart Hermes; do not alter live ledger or account reset state.
- `test_observed_peak.py` seeds disposable event/request SQLite records and exercises matched interval boundaries, carried-in children, duplicate identities, exact excluded notification counts, durable sequence pairing under clock shifts, request-derived model/provider attribution, scoped child-request evidence, page-independent totals, profile-qualified union and lifecycle recomputation on signed event-only refresh (plus old-receipt full fallback). A small synthetic check counts lifecycle pairing scans across multiple changed request buckets; it does not demonstrate live speed or complete lifecycle capture.
- `test_provider_trend.py` checks real disposable SQL bucket/provider partitions with differing shapes, full-window page independence, token/cost missing coverage, all-profile merging and unreadable-source partial coverage, plus signed changed-bucket refresh versus a full read across minute, two-minute, hourly and daily resolutions with a selected provider filter, and a signed legacy peak-capable receipt missing provider partitions that must fall back to an exact full response. This is fixture evidence, not a live data read.
- The Skills fixture covers preflight-only future catalogue inclusion, content-free persistence, requested-model/period filtering and aggregate-only reads while preserving legacy observations. Never backfill history from the current catalogue.
- `test_selected_snapshot.py` proves a raw-copy SnapshotBusy under fixture WAL checkpoint/reset, coherent selected GET and refresh POST while ordinary WAL writes continue, committed WAL inclusion, bounded real-exclusive-lock failure, busy-callback cleanup and retryable route errors. Selected `mode=ro` connections may affect fixture source WAL/SHM sidecars; assert unchanged usage rows apart from the fixture writer. All-profile regression tests retain strict no-source-sidecar raw-copy semantics.
- The old-selected-marker cap test uses isolated FastAPI requests with 101 newer persisted test rows per synthetic profile; it checks bounded prefix order, factual window, missing/recent dedup, qualified all-profile selection and no cross-profile marker fact.
- `test_anthropic_pricing.py` uses synthetic fixtures shaped like Anthropic's official pricing/model pages (synthetic model names) and disposable ledgers. It covers exact model IDs and documented aliases only, standard/fast/geo tiers and context-window boundaries, and exact cache-TTL write costs, with unknown results for a missing or inconsistent split. It also covers saved completion prices with immutable retrospective projection parity (unchanged bytes) and host-exact endpoint provenance (`first_party`/`custom`/unverified) for sync and async auxiliary captures. Parser/crawl drift fails closed. The test uses no network, accounts or live ledgers and proves parser/accounting behaviour, not live compatibility or actual charges.
- `test_native_provider_capture.py` skips unless `HERMES_CAPTURE_CORE` names a read-only Hermes source tree. It AST-loads only the named core definitions (main `_StreamingCall._call_anthropic`, `_dispatch_nonstreaming_api_request` → `_anthropic_messages_create` → `create_anthropic_message`, the `anthropic_adapter` stream helpers, the relay accumulator and the auxiliary relay funnel/client classes). Hermes startup, the SDK, Relay managed execution and transports are fakes. Run it with a disposable `HOME`/`HERMES_HOME` and refused network. When core changes a helper those paths import, copy that helper from core; do not stub it. The stream/non-stream/auxiliary cases check endpoint class, returned enums, native-usage priority and saved cost against the synthetic catalogue (first-party priced, custom unpriced). Two Relay-mode cases execute the whole core `relay_llm.py` (`ManagedLlmStream`) under the real `_StreamingCall._call_anthropic` with SDK-shaped pydantic events (unset fields `None`): managed mode (fake `relay_runtime` resolution plus a fake `stream_execute` that runs the collector) must capture native usage through `on_chunk(_jsonable(event))`; unmanaged mode must never call `on_chunk` and capture the final message through core's `_usage_summary_for_api_request_hook` wrapped by the plugin's `raw_wrapper`. This shows compatibility with that source tree only, not with a live provider or charge.
- `test_profile_secret_scope.py` runs the actual plugin through the installed Hermes interpreter (skipped if absent) with disposable `HOME`/`HERMES_HOME`, fake tokens, multiplexing on, refused sockets and an `httpx` MockTransport: concurrent own/foreign/empty-profile quota workers must reach only the mocked usage GET with their own token, clean up after exceptions (plain and prepared homes), and change no existing fixture file (host-seeded non-credential files are allowed). A synthetic in-process failing secret source (no helper process) registered for the foreign profile counts host hydration attempts: exactly one per payload build, one per standalone reset/Nous operation. Fake host modules cover legacy and partial-API compatibility. Route tests (FastAPI TestClient, fake host modules) cover: partial API → `configured: null`/`scope_unavailable` with `credential_discovery.status: unavailable`, or 503 without recorded activity, with no discovery/probe/snapshot write; unrelated failures still 500; a failing-hydration counter proving one hydration and 12 per-worker binds of a private scope copy per `/usage` build, none on a cached read; and standalone reset binding preparing per operation.
